# Отдельный тип Codex Light в Баксе

Пакет реализует движок; сервер и iOS развиваются отдельно. Нативная интеграция добавлена
в Бакс 0.72.0 и сервер 0.44.0. `--compat-claude-lite` остаётся для старого сервера с
отдельным Claude Code Lite агентом. Ниже — контракт потребителя протокола.

## Сервер

1. `codex_light` в перечислении движков; своя таблица каталога, создание агента и ключа.
2. Правило Lite: один агент обслуживает один непустой `session_id`. Вторая сессия
   получает `agent_busy`, а не вытесняет первую. Переподключение той же сессии допустимо.
3. Общая привязка ключа к `install_id`, HMAC и релей без хранения переписки.
4. Настройки модели/effort Бакса не применяются к уже открытой сессии Codex.

## iOS

Тип «Codex Light» в DTO, выборе движка, подписях и инструкции подключения.
Кнопки определяются `caps`:

```json
{"v":1,"type":"caps","mode":"lite","supports":["subscribe","run","answer","history","files.list","files.read"],"remember":false}
```

Принять новый кадр:

```json
{"v":1,"type":"question.resolved","question_id":"card-uuid","session":"thread-id"}
```

Карточка закрывается, если ID совпадает. Старый клиент игнорирует этот кадр, но мост
всё равно отклоняет запоздалый ответ. При нескольких вопросах мост показывает
одну карточку, после ответа — следующую, затем отправляет Codex общий результат.
Общие ошибки Lite формируются из фактического движка.
Фоновые tasks, model/effort, sessions, compact, attachments и cancel не заявлены в caps.

## Приёмочный прогон с телефоном

1. Отдельный тестовый ключ → регистрация → `doctor --check-history` → MCP → `bax_status`.
2. История, пагинация, чтение файлов на телефоне.
3. Текстовая задача: один user-message, поток и окончательный ответ.
4. Вторая задача во время работы: приём в очередь, выполнение после завершения первой.
5. Allow/deny команды и изменения файла без постоянных правил.
6. Ответ в терминале: закрытие карточки на телефоне, отклонение старого ответа.
7. Вторая сессия с тем же ключом: первая остаётся владельцем агента.
8. Обрыв/возврат сети: тот же thread, без двойного выполнения задачи.
9. Закрытие MCP: агент офлайн, Codex продолжает работать.

Этот прогон требует действующего Бакса; автоматические локальные тесты его не заменяют.
