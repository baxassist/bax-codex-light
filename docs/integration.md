# Отдельный тип Codex Light в Баксе

Пакет реализует движок; сервер и iOS развиваются отдельно. Нативная интеграция добавлена
в Бакс 0.72.0 и сервер 0.44.0. `--compat-claude-lite` остаётся для старого сервера с
отдельным Claude Code Lite агентом. Ниже — контракт потребителя протокола.

## Сервер

1. `codex_light` в перечислении движков; своя таблица каталога, создание агента и ключа.
2. Правило Lite: один агент обслуживает один непустой `session_id`. В 0.4.0 это стабильный
   ID контроллера проекта `project:<hash>`, а не выбранного разговора. Смена сессии не
   переподключает релей. Второй владелец получает `agent_busy`; локально владельца защищает flock.
3. Общая привязка ключа к `install_id`, HMAC и релей без хранения переписки.
4. Настройки модели/effort Бакса не применяются к уже открытой сессии Codex.

## iOS

Тип «Codex Light» в DTO, выборе движка, подписях и инструкции подключения.
Кнопки определяются `caps`:

```json
{"v":1,"type":"caps","mode":"lite","supports":["subscribe","run","answer","history","files.list","files.read","power.get","power.set"],"remember":true}
```

Принять новый кадр:

```json
{"v":1,"type":"question.resolved","question_id":"card-uuid","session":"thread-id"}
```

Карточка закрывается, если ID совпадает. Старый клиент игнорирует этот кадр, но мост
всё равно отклоняет запоздалый ответ. При нескольких вопросах мост показывает
одну карточку, после ответа — следующую, затем отправляет Codex общий результат.
Общие ошибки Lite формируются из фактического движка.
Прежний mode=lite не заявляет sessions/cancel. С 0.4.0 mode=project объявляет
`sessions.list`, `session.select`, `session.close`, `cancel`; требуется Бакс 0.75.5+.
Model/effort, compact и отдельные background tasks не заявлены. С 0.4.1 `run.attachments`
принимает JPEG/PNG/WebP/GIF в base64: до 8 картинок, 6 МиБ каждая, 8 МиБ вместе.
App-server получает штатные `image` inputs с data URL и точным thread/turn ID.
В состоянии проекта сохраняются только текст и число картинок неподтверждённой задачи;
автоматического повтора после аварии нет. Вложения остаются в истории Codex.

С 0.4.2 `thread/start` явно выбирает поддерживаемый `historyMode=legacy`; тип
`ThreadHistoryMode` берётся из закреплённого SDK (в start params SDK 0.160.0 поле отсутствует).
`thread/name/set` сохраняет пустой разговор до его выбора, без `turn/start`.
Точный отказ `thread/items/list is not supported yet` включает штатное чтение полных
ходов через `thread/turns/list` с opaque cursor. Прочие ошибки истории не скрываются.
Известные контроллеру открытые пустые разговоры добавляются на первую страницу списка,
если Codex их пока не включил; архив/следующие страницы продолжают читаться из app-server.

## Контроллер проекта (0.4.0)

В 0.4.3 `bax_status.async_questions` возвращает ID и текст только асинхронных вопросов
разговора вызывающего MCP. `bax_resolve_question(question_id)` закрывает конкретную
карточку через `question.resolved`, без `turn/start`, `turn/steer` или RPC ответа на разрешение.
Скрыть запрос командного, файлового или сетевого разрешения этим методом нельзя.
Структурированный `userMessage` с точным заголовком вопроса и `Ответ:` снимает карточку
автоматически. Обычный свободный текст требует явного решения модели через MCP.
Если MCP не получил ID из метаданных, `thread_id` передаётся явно из `CODEX_THREAD_ID`
и проверяется через `thread/read`; выбранный разговор, модель и разрешения сохраняются.

`serve` — MCP-прокси с точным ID своего чата. Он автоматически находит один локальный
контроллер проекта через приватный Unix WebSocket (0600), не выбирая себя на телефоне.
`bax_attach` явно выбирает разговор своего проекта. Контроллер переживает EOF MCP;
shutdown для обновления допустим только при отсутствии активных задач, вопросов и доставок.
После аварийного перезапуска выбранный ID восстанавливается из файла состояния, а
неподтверждённая доставка остаётся видна и автоматически не повторяется.

- `sessions.list {archived,cursor}` → `sessions {items,archived,next_cursor,append,selected}`.
  Каталог и архив читаются из Codex, cwd сверяется. Дочерние разговоры исключены.
- `session.select {session,expected_session,archived,rid}` → `session.changed {session,title,rid}`.
  `session="new"` создаёт разговор с настройками выбранного; `archived=true` возвращает из архива.
- `session.close {session,expected_session,rid}` архивирует только свободную сессию без
  ожидающих вопросов/доставок. `cancel {session}` останавливает точный ход, включая фоновый.
- `run`, `answer`, `history` и все кадры переписки содержат точный `session`.
  Прежний экран не может отправить задачу в новую сессию. Фоновый статус приходит как
  `session.status`; фоновые кадры не добавляются в выбранную ленту телефона.
- `history.done` завершает пачку, включая пустую историю. `question.resolved` относится
  только к вопросу своей сессии. Реальные RPC остаются живыми подписками, без авторазрешений.

Историю читает `thread/items/list` из сохранённых сессий Codex. Собственного журнала
ответов или очереди сообщений фоновых сессий нет. Состояние содержит только выбор,
параметры для новой сессии и небольшие сведения о неподтверждённых отправках.
Внутренние JSONL Codex напрямую не разбираются: текущая схема проверяется официальным SDK.

С 0.3.5 permission-карточка включает `remember` и `remember_label`. Если для запроса
сохранение не поддержано, `remember=false` скрывает вариант. При `remember=true`
третья кнопка использует `remember_label`: «Разрешить всегда» или «Разрешить на диалог».
В `rule` и тексте карточки видны точное правило и срок. Ответ `allow, remember=true`
выбирает сохранённый вариант из исходного запроса Codex; поля правила/путей из ответа
телефона игнорируются. `availableDecisions` ограничивает решения команд. Для постоянного
правила требуется точное предложенное Codex начало команды или правило адреса.
Для файлов требуется абсолютный `grantRoot`; дополнительный профиль действует с
`scope=session` только до конца текущего диалога. Старые клиенты используют переключатель.

## Настройка защиты от сна (0.3.6)

Бакс 0.75.3 показывает «Настройки» только при объявленном `power.get`.
`power.get` возвращает текущее состояние; `power.set` принимает строго булево
`keep_awake`. Ответ `power.settings` содержит `enabled`, `supported`, `active`, `error`
и исходный `rid`. Выключение сразу снимает защиту; успешное сохранение переживает
перезапуск моста и переподключение. По умолчанию `enabled=true`.

Выбор хранится отдельно от регистрации, по абсолютной папке проекта и UUID агента.
Невозможность сохранения возвращает прежнее значение и понятную ошибку; соединение
сохраняется. Другой UUID отклоняется. Настройки модели, sandbox и approvals не меняются.
На Linux `supported=false`, приложение выключает доступность переключателя и объясняет
ограничение. Релей пересылает новые кадры без дополнительной серверной ручки.

## Приёмочный прогон с телефоном

1. Отдельный тестовый ключ → регистрация → `doctor --check-history` → MCP → `bax_status`.
2. История, пагинация, чтение файлов на телефоне.
3. Текстовая задача: один user-message, поток и окончательный ответ.
4. Комментарий во время работы: `turn/steer` в точный текущий ход.
5. Allow/deny команды и изменения файла: один раз; отдельная третья кнопка для срока,
   действительно предложенного Codex. Отказ не создаёт правила.
   Дополнительный доступ: `item/permissions/requestApproval` → `kind=permission` →
   allow/deny → только запрошенные permissions / пустые permissions, `scope=turn`.
   Третья кнопка для дополнительного доступа → только запрошенный профиль, `scope=session`.
   Локальный режим Codex не менять ради теста: Approve for me сохраняется; уведомления
   автоматической проверки не становятся карточками. Человеку показываются настоящие RPC.
6. Ответ в терминале: закрытие карточки на телефоне, отклонение старого ответа.
7. Выбор/создание второй сессии: первая продолжает работу в фоне; её история и вопросы
   видны после возвращения. Закрытие свободной и восстановление из архива.
8. Обрыв/возврат сети: тот же thread, без двойного выполнения задачи; после `ready`
   задержка сброшена, повтор через секунду, предел длительного сбоя — 30 секунд.
9. Закрытие MCP: контроллер остаётся на связи, Codex продолжает работать.

Этот прогон требует действующего Бакса; автоматические локальные тесты его не заменяют.

## Контекст и сжатие

`context.get` / `session.compact`: `session`, `expected_session`, `rid`.
Оба ID обязаны совпасть с выбранным разговором. Сжатие допустимо только при native
`thread.status.type=idle`; используется SDK `thread/compact/start`, без resume,
interrupt или изменения параметров. Повтор во время сжатия отклоняется.

Ответ `context.history`: `session`, `rid` (у ответа на запрос), `compacting`,
`available`, `items` и необязательный `error`. До 100 последних записей точного
журнала: `{id, at, before, after}`, `at` — Unix seconds; замер — `{used, max, model}`
или null. `used` берётся из `last_token_usage`, не суммарных расходов. Первый замер
после сжатия не заменяется дальнейшими. Пропавший/непроверенный журнал даёт
`available=false`. Текст сводки и предполагаемый инициатор не передаются.
После native completion контроллер отправляет новый журнал; приложение также
перечитывает его, пока окно открыто. Старые плагины не объявляют эти capabilities.

## ERR-1: совместимые ошибки wire v1

Расширение `error` не меняет `v=1`. Обязательны прежние `code`, `message`; optional:
`error_id`, `scope` (`session`/`connection`), `source` (`codex`/`plugin`/`relay`/`app`),
`operation`, `session`, `turn_id`, `rid`, `category`, `native_code`, `delivery`,
`action`, `will_retry`. Идентификатор содержит операцию, ID хода/запроса и код;
разговор входит в клиентский ключ. Одинаковый сбой через live/completed/subscribe
обновляет одну карточку; одинаковый текст разных ходов не объединяется.

`codex_turn_failed` означает сбой выполнения **принятого** хода (`delivery=accepted`),
не потерю пользовательского сообщения. Категории: capacity, quota, rate_limit,
context, authentication, permission, policy, request, provider, connection, history,
timeout, delivery, unknown. Основной источник — официальный `codexErrorInfo`;
для старого capacity-текста есть совместимый fallback. Неизвестный безопасный текст
остаётся видимым. `additionalDetails`, raw RPC, credentials, URL и локальные пути
в публичные подробности не попадают.

`delivery=rejected` — подтверждённый отказ, `unknown` — нет подтверждения,
`not_applicable` — операция не связана с приёмом задачи. Неизвестная доставка
не повторяется автоматически. `rid` команды run сохраняется в outbox при перезапуске.
Эхо означает приём мостом; выполнение модели подтверждается независимо.

`will_retry=true` приходит только из native Codex: мост не повторяет запрос.
При успехе `error.resolved` с `session`, `turn_id` снимает временную карточку;
окончательные ошибки остаются в истории. При позднем подтверждении доставки
`error.resolved` содержит `rid`, `error_id`, `delivery=accepted`: снимается только
предупреждение соответствующей команды, а не ошибка выполнения модели. Последние 100 ходов читаются через
`thread/turns/list` с `itemsView=notLoaded`; ошибки видимых ходов и последнего запроса
приходят после `history.done`. Своя база переписки не создаётся.
`sessions.items[].last_error` — optional описание последнего сбоя отдельно от
доступности ready/busy. Новый ход очищает последнюю ошибку, сохраняя историческую.

`action` — подсказка, без автоматического исполнения: choose_model, compact,
check_limits, wait, open_codex, edit_request, check_history, reload_history, none.
Для `model.settings` совместимый `error` дополнен `error_details` той же схемы.
Старые клиенты читают безопасную строку, новые — причину и диагностические поля.

## Статус сессии (0.5.6)

Capability `session.status.get`: телефон отправляет `session`, `rid`. Плагин
проверяет выбранный разговор и cwd через thread/read и возвращает `session.details`
с теми же session/rid. Модель/провайдер берутся из thread, остальные эффективные
параметры — из подтверждённого ответа thread/resume этой сессии. Неизвестные
значения остаются null. `instructions` — только пути источников, без содержимого.
`account` содержит тип/тариф без email, accountId и токенов.
`limits` — список всех primary/secondary окон из rateLimitsByLimitId с id/name,
used_pct, minutes и resets_at; резервные окна не теряются.

account/read и account/rateLimits/read проверяются типами официального SDK.
Параметры refreshToken/supportsLunaReserve не включаются: запрос не обновляет вход
и не включает эксперимент резервного тарифа. При недоступности аккаунта/лимитов
возвращается частичный снимок и список unavailable.
Телефон отбрасывает чужие и устаревшие ответы по agent/session/rid. Старый плагин
не получает неизвестной команды; экран показывает известный контекст и соединение.
[Официальный контракт Codex App Server](https://learn.chatgpt.com/docs/app-server).

## Автозапуск после позднего ID (0.5.7)

Когда CODEX_THREAD_ID не передан в MCP, start не угадывает разговор и не сканирует
каталог. Поздний bax_status(thread_id) проверяет ID/cwd через официальный thread/read,
после чего запускает фоновый auto_discover. Уже сохранённая выбранная сессия
восстанавливается контроллером. Сам status не вызывает attach. При потере
контроллера завершённый discovery запускается снова; занятое обновление сохраняет
свой штатный цикл ожидания. Повторная проверка статуса подтверждает connected.


## Установленные скиллы (0.5.8)

Capability `skills.list`: запрос `{type: "skills.list", rid}` → ответ
`{type: "skills", rid, skills: [{name, description}], error?}`.
Источник — официальный App Server `skills/list` для cwd проекта, `forceReload=true`;
только enabled, сортировка по имени, без содержимого файлов и локальных путей.
Каталог не меняет сессию, модель или разрешения. При ошибке сканирования ответ
содержит ошибку, не выдаёт пустой список за успешный результат.
В тексте задачи используется `$name`, как описано в
[официальном API](https://learn.chatgpt.com/docs/app-server#skills).

## Явная запись результата в Поток (0.5.9)

С 0.5.10 серверный отказ преобразуется в MCP `isError=true`. Сервер 0.49.22
возвращает в подтверждении `error:{code:"stream_disabled", message:...}`,
`published:false` и совместимый `reason`. Галочка проверяется под блокировкой
перед каждым вызовом, до дедупликации; выключена — повтор тоже отклоняется.
Ошибку получает вызывающий агент, соединение остаётся действующим.

MCP `bax_publish(text, publication_key, thread_id="")` проверяет точный разговор
и его проект без выбора сессии. IPC `publish_to_feed` отправляет через существующий
канал кадр `{type:"feed.publish", rid, text, publication_key}`. Сервер 0.49.21+
берёт agent/user из авторизованного соединения, игнорируя подставленный agent.
Ответ только вызывающему соединению: `{type:"feed.published", rid, published,
reason?, event_id?, duplicate?}`. Текст 1–10000 символов, ключ 1–128 символов.
Ключ постоянен для одного результата; конфликт текста возвращает
`publication_key_conflict`, старую запись не переписывает. При `stream_disabled`
новая запись отсутствует. Старые записи/скрытие/закрепления сохраняются.
Тайм-аут подтверждения — `published:null`, повтор безопасен с тем же ключом.
Статус «busy → ready» и обычные ответы не являются публикацией.

При `session.select(new)` сервер добавляет текущий `feed_prompt` агента, независимо
от присланного телефоном поля. Контроллер передаёт пользовательский текст один раз
в `thread/start.developerInstructions` (тип официального SDK), с указанием инструмента
`bax_publish`. Пустой текст не добавляет инструкции. `thread/resume`, смена выбранной
сессии и восстановление соединения не добавляют промпт и не запускают отдельный ход.
Изменение промпта относится к новым сессиям, созданным из Бакса; локальные разговоры
Codex, созданные напрямую, не переписываются. Шаблон конфигурации не хранит промпт.
