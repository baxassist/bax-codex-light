# Автоматическое подключение разговоров Codex

## Решение

Обычная команда `codex` сохраняется. После согласованной однократной настройки
функция оболочки запускает интерактивный Codex с явным локальным `--remote`.
Штатный daemon запускается только при необходимости; embedded fallback исключён.
Служебные команды, включая exec/plugin/login/logout, передаются нативному CLI.
Интерактивные /logout и повторный вход выполняются тем же AppServer.
Отдельные `codex login/logout` остаются нативными командами и не синхронизируют
автоматически кеш авторизации уже работающего daemon.

Поддержаны macOS/Linux, zsh, интерактивный bash и CLI >=0.166. Для login bash
профиль должен читать .bashrc. Windows/fish, Desktop backend и подключение уже
работающего embedded разговора этим механизмом не поддерживаются. Не обходить
active writer, не копировать токены и не завершать процессы ради подключения.

## Состав

- `setup`: предварительная проверка, просмотр правки, явное применение, backup,
  идемпотентное повторение и удаление только неизменённого собственного блока.
  Существующие alias/functions, symlinks и ручные правки не перезаписываются.
- Независимый launcher сохраняется вне каталога версии плагина. Новый hook обновляет
  только собственный файл по хешу, не меняя rc и не понижая версию из старого окна.
- Асинхронные command hooks SessionStart (startup/resume/fork/clear) и
  UserPromptSubmit регистрируют точный ID/cwd. Prompt не сохраняется и не логируется.
  Незарегистрированные проекты пропускаются. Compact не выбирает разговор заново.
- Контроллер подтверждает ID, проект и загруженность в AppServer, подписывается
  на разговор и сохраняет выбор телефона. Только первый разговор при пустом выборе
  становится выбранным. Повторные события идемпотентны, offline-сессия переподписывается.
- При гонке готовности hook повторяет регистрацию до 30 секунд; следующая отправка
  пользователя повторяет попытку. Hooks требуют разрешения Codex; оно не обходится.
- Контроллер не переиспользуется для другого endpoint. Окончание сессий отслеживается
  существующими событиями AppServer, не принудительным завершением из SessionEnd.
- `doctor` показывает loaded/authentication. notLoaded относится к конкретному
  AppServer, а не ко всем окнам Codex. Проверка аккаунта не выполняет login/refresh.

Регистрация и список разговоров не означают успешную доставку. Очереди сохраняют
привязку к аккаунту: старая задача A не исполняется при B; неопределённая доставка
не повторяется. При отключении интеграции регистрация, история и процессы сохраняются.

## Проверки 0.5.40

Полный набор: **421 PASS, без skip**, 60,79 с; locked sync, Ruff check/format и diff check.
Native пустые сессии, регистрация, повтор, reconnect/archive проверены отдельно на
реальных изолированных AppServer CLI0.160 и CLI0.166, без запуска модели.
Смена A→logout→B и новая сессия проверены через RPC-имитатор: старая очередь A
сохраняется, новая задача B адресуется только B, выбранная сессия не меняется.
Проверены настоящая zsh-функция с пробелами/литеральными аргументами, отказ daemon,
установка/повтор/удаление/обновление, сохранность пользовательских правок и отказ записи.
Сохранены исходные FAIL диагностики и гонки теста готовности, затем GREEN.

Это не проверка двух реальных ChatGPT-аккаунтов и не подтверждение доверия hooks
в пользовательском терминале. Полная пользовательская приёмка остаётся отдельно:

1. Разрешить hooks и открыть новый терминал обычным codex после настройки.
2. A: зарегистрировать root, выполнить задачу с телефона.
3. /logout → вход B → новая сессия; без просьбы модели увидеть её на телефоне.
4. Проверить новую задачу B и сохранность старой очереди A.
5. Вернуться A; проверить два терминала, fork, смену выбора на телефоне и reconnect.
6. Проверить, что закрытие окна не прерывает чужой разговор; удалить интеграцию,
   сохранив ручные настройки и процессы.
