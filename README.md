# Bax Codex Lite

В 0.5.9 добавлена явная команда `bax_publish(text, publication_key, thread_id)`:
значимый результат с деталями выпуска попадает в Поток только по вызову агента.
Обычные ответы/статусы публикацию не вызывают. `publication_key` — постоянное имя
результата, например `ios-0.77.8-205` или `plugin-0.5.9`; повтор не создаёт дубль.
`published=true` подтверждает запись, `false` с `stream_disabled` означает, что
галочка выключена и событие не создано; `null` — нет подтверждения, повторить можно
с тем же ключом. Команда доступна в режиме проекта, требует сервер 0.49.21+.
Публикуйте только по поручению человека или постоянным правилам проекта;
не меняйте переключатель ради публикации и не пересылайте всю переписку.

В меню агента «…» → «Промпт Потока» пользователь меняет правила значимости.
При создании сессии из Бакса сервер передаёт актуальный `feed_prompt`, он входит
один раз в начальные инструкции `thread/start`. Возврат к существующей сессии
и переподключение не добавляют его заново. Пустой промпт отключает эту вставку;
переключатель «Уведомлять в Поток» независимо разрешает саму публикацию.

В 0.5.8 телефон получает список включённых установленных скиллов проекта через
штатный `skills/list`. Выбор вставляет `$skill-name` в черновик задачи, не запускает ход.
Список обновляется с диска при открытии; ошибка чтения показывается явно.

В 0.5.7 исправлен автозапуск: если Codex не передал ID разговора при старте MCP,
проверка `bax_status(thread_id)` валидирует точный разговор и запускает отложенный
контроллер. Потерянный контроллер восстанавливается при проверке статуса.
Выбранная сессия, регистрация и разрешения сохраняются.

В 0.5.6 добавлен снимок статуса выбранной сессии для телефона: параметры,
источники инструкций, аккаунт и все доступные окна лимитов. Запрос только читает
Codex App Server, не запускает ход и не меняет модель или разрешения.

В 0.5.4 выпущен ERR-1: причины и области ошибок, идентичность хода/команды,
состояние доставки, native retry и позднее подтверждение. Сохраняется wire v1.
Проверки пройдены; опубликованная версия — 0.5.4.
Подробности — [контракт интеграции](docs/integration.md).

В 0.5.3 исправлено подтверждение ручного сжатия: запрос подтверждается отдельно от
завершения, новая запись точного журнала снимает ожидание даже без live-события.
Тайм-аут RPC не отменяет уже запущенную операцию и не приводит к повторной команде.

В 0.5.1 исправлена повторная загрузка длинной истории: пересечение страниц,
изменившийся порядок live-событий и исчерпание промежутков между локальными ID
не требуют перезапуска моста. Полная загрузка заново нумерует снимок ленты;
сам разговор, его контекст и разрешения остаются в Codex. При старом курсоре
нужно заново открыть переписку. Процент показывает остаток окна последнего запроса,
а не накопленный расход: после сжатия контекста он закономерно увеличивается.

Плагин Codex для Бакса: один агент подключён к **проекту**, на телефоне можно создать,
выбрать, закрыть и вернуть разговор. При переключении прежняя задача продолжает работать
в фоне, её ответы и вопросы остаются в своей сессии. Историю хранит Codex; отдельной базы
переписки нет. Новые разговоры наследуют модель и разрешения выбранной сессии.
Для управления проектом нужен Бакс **0.75.5 или новее**. Проверено на Mac; пользователь
подтвердил штатный запуск прежней 0.3.1 на Ubuntu. Windows пока не поддержан.

В 0.5.0 добавлены переименование разговора с телефона, остаток контекста по последнему
запросу Codex, документы вместе с фотографиями и реальные фоновые терминалы.
Эти элементы доступны в Баксе 0.77.0. Документы сохраняются в закрытой папке
`.bax-attachments` внутри проекта и исключены из обычного `git add`; модель получает
точные пути. До 8 вложений: до 6 МиБ каждое и до 8 МиБ вместе. Картинки по-прежнему
передаются штатным image input.

Фоновые процессы запрашиваются через документированные экспериментальные методы
`thread/backgroundTerminals/list` и `thread/backgroundTerminals/terminate`:
<https://learn.chatgpt.com/docs/app-server>. SDK 0.160.0 пока не содержит их типов;
их схемы проверяются отдельными Pydantic-моделями. Если установленный app-server
не поддерживает методы, телефон покажет причину, а не пустой список. Остановка
проверяет точный разговор и processId и не прерывает остальные разговоры.

С версии 0.5.5 отложенное обновление проверяет свободный промежуток каждые
250 мс: короткая пауза между задачами больше не теряется из-за сетевого backoff
до 30 секунд. Работающие ходы, доставки и вопросы по-прежнему защищены.

## Подключить на Mac

Нужны Codex с поддержкой плагинов и локального shared app-server, Python **3.11 или новее**
и агент **Codex Light** в приложении Бакс. Проверено на Codex CLI 0.160.0, Python 3.14.2.
Каталог плагина — [baxassist/bax-codex-light](https://github.com/baxassist/bax-codex-light).

1. Один раз выполните в Терминале:

   ```bash
   codex plugin marketplace add baxassist/bax-codex-light
   codex plugin add bax-codex@baxassist
   ```

   Плагин использует штатную систему установки Codex. Редактировать `config.toml` не нужно.
   Если `codex` не найден, установку можно выполнить встроенным CLI вашего приложения Codex.

2. Перезапустите Codex и откройте разговор в проекте, например в папке вашего сайта.
3. В Баксе откройте агента Codex Light → «Интеграция» → «Скопировать команду для Codex».
   Вставьте её в нужный разговор. Команда содержит регистрацию и адрес сервера; плагин
   сохранит её для папки этого проекта. Когда агент станет зелёным, можно писать с телефона.

В следующих разговорах этого проекта достаточно попросить:

> Подключи этот чат к Баксу.

Для автоматического подключения скопируйте в Баксе правило проекта из инструкции
нового агента и добавьте его в `AGENTS.md`. Правило действует с первого задания:
проверить `bax_status`, взять точный `caller_thread_id` или `CODEX_THREAD_ID`, выбрать
этот разговор через `bax_attach` при необходимости и проверить `connected=true`.
Регистрация и разрешения сохраняются; основной разговор выбирается один раз,
без переключений при каждом сообщении и из фоновых задач. Не записывайте ключ в `AGENTS.md`.

Обновить уже установленный плагин:

```bash
codex plugin marketplace upgrade baxassist
codex plugin add bax-codex@baxassist
```

После обновления перезапустите Codex. Сохранённое подключение проекта останется.

Плагин не выбирает последний разговор: навык получает **точный** `CODEX_THREAD_ID`
текущего чата. Папку берёт из метаданных этого разговора. Если MCP уже получил ID,
MCP находит контроллер проекта без смены выбранной сессии; навык вызывает `bax_attach`
только по просьбе подключить этот чат. Если поверхность не даёт ID
или shared app-server, плагин сообщает об этом, вместо подключения к другому разговору.

### Первый запуск

Плагин запускается установленным `python3`. Старый системный Python на Mac используется
только для поиска Python 3.11+ в обычных местах установки. Python сам не скачивается.

При первом запуске плагин создаёт отдельное окружение в `~/.bax/codex-runtime` и скачивает
библиотеки из PyPI. Это может занять пару минут; нужен интернет. Следующие запуски используют
готовое окружение. Не нужны Node.js, uv, ручной `pip install` или отдельное Mac-приложение.
Другие Python-библиотеки пользователя не меняются. Параллельные запуски ждут общей установки.

С версии 0.3.2 MCP помечен `required`: Codex ждёт его инструменты перед первым запросом
в пределах `startup_timeout_sec = 240`. Это устраняет пропуск плагина из первого каталога,
когда холодный запуск дольше стандартного ожидания optional MCP (1 секунда). Если Python
или установка библиотек недоступны, Codex покажет ошибку запуска. Ручной сервер не нужен.
В журнале MCP видны длительность подготовки библиотек и использование готового окружения;
stdout остаётся только для протокола MCP.

Подключение к локальному Codex происходит в фоне после запуска MCP. Даже если сокет
недоступен, все инструменты остаются доступны. `bax_status` сообщает `error_code`,
понятную причину и действие для восстановления; плагин повторяет подключение самостоятельно.

Версии зависимостей и хеши закреплены в `plugins/bax-codex/requirements.txt`, установка
использует только готовые wheels. Внутри — официальный MCP SDK, `websockets` и типы
официального `openai-codex==0.160.0`. STDIO и WebSocket framing вручную не реализуем.

## Что умеет

- Текстовая задача, диктовка и картинки с телефона → текущий разговор Codex; ответ приходит на лету.
- «Сессии проекта»: новый разговор, выбор открытого, закрытие свободного в архив,
  возвращение из «Закрытых», остановка конкретной задачи. Переключение сохраняет фоновую работу.
- История из app-server Codex, пагинация по 50 сообщений; своей базы переписки нет.
- Разрешение команды или изменения файла → карточка телефона на одно действие; при
  поддержке Codex можно сохранить предложенное правило или подтверждение до конца диалога.
- Дополнительный доступ к сети и файлам → карточка на текущий ход или до конца диалога.
- Ответ на вопрос в самом Codex закрывает ту же карточку на телефоне.
- Файлы проекта только для чтения: отслеживаемые Git текстовые файлы до 256 КиБ.
- Переподключение после обрыва; неопределённо доставленная задача не отправляется повторно.
  С версии 0.3.5 успешное `ready` сбрасывает накопленную задержку: первая повторная попытка
  через секунду, предел при длительной недоступности — 30 секунд. В статусе есть время
  последнего подключения/отключения и код/причина закрытия WebSocket без секрета регистрации.
- На Mac с версии 0.3.3 подключённый мост удерживает систему от автоматического сна.
  Экран может гаснуть, блокировка и ручной сон работают как обычно. Используется штатный
  `caffeinate -i -w <PID контроллера>`: защита снимается при завершении контроллера, включая аварийный выход.
  Во время переподключения защита сохраняется. Общие настройки энергосбережения не меняются.
  Состояние видно в `bax_status.keep_awake`; ошибка защиты не мешает запуску MCP.
  С версии 0.3.6 защиту можно выключить в Баксе: меню агента → «Настройки» →
  «Защита от сна» (Бакс 0.75.3). По умолчанию включена. Выбор применяется сразу и
  сохраняется отдельно для агента и папки проекта в `~/.bax/codex-light-settings.json`.
  Регистрация и настройки Codex не меняются; Linux показывает, что защита доступна на Mac.

С версии 0.3.8 сообщение с телефона во время работы сразу направляется в **текущий ход**
через `turn/steer`: можно уточнять задачу, исправлять решение и отвечать, пока Codex работает.
Если мост подключился посреди хода, он читает ID активного хода только этого разговора,
без загрузки переписки. Когда разговор свободен, сообщение начинает следующий ход.
Очередь до десяти сообщений остаётся для случаев, когда немедленная доставка недоступна.
Эхо подтверждает приём сообщения плагином, а не то, что модель уже прочла его.
При повторном открытии агента на телефоне ожидающие сообщения
показываются вместе с историей Codex. Если доставка не подтверждена или Codex отклонил
запрос, текст и объяснение остаются видны до подтверждения в истории. Перед повторной
отправкой проверьте разговор: неопределённо доставленное сообщение автоматически не повторяется.
После явного отказа, если ход сменился или закончился, мост один раз сверяет состояние
и доставляет в точный доступный ход. Повторный отказ сохраняет очередь с понятным сообщением.
Поздний ответ на асинхронный вопрос не вмешивается в другой активный ход, но его ожидание
не задерживает новые комментарии к текущей задаче. Разрешения автоматически не выдаются.
С версии 0.4.0 один постоянный контроллер обслуживает проект независимо от MCP отдельных
окон. Закрытие MCP сохраняет канал и фоновые задачи. Состояние выбора и небольшие записи
неподтверждённой доставки сохраняются в приватном файле; после аварийного перезапуска
доставка не повторяется автоматически. История фоновых разговоров читается через
`thread/items/list` из сохранённых сессий Codex, без отдельной очереди ответов и прямого
разбора внутренних JSONL. Живые подписки нужны для завершения хода и настоящих RPC разрешений.

Все команды и ответы имеют точный `session`; устаревшая команда с другого экрана не
перенаправляется в новый разговор. Создание/закрытие проверяет `expected_session`.
Новая сессия наследует model/provider/effort, approval policy/reviewer и эффективный sandbox;
если Codex вернул другие настройки, задачи в неё не отправляются. Закрытие архивирует
историю, работающую сессию сначала нужно остановить, а ожидающий вопрос — разрешить.
Архивирование одного разговора не отключает проект и не выбирает другой автоматически.

С версии 0.4.2 пустой разговор сохраняется через штатное `thread/name/set` до выбора:
не требуется первое сообщение модели. Создание использует поддерживаемый `legacy`
формат истории; paginated creation в CLI 0.160.0 ещё не поддержан. Когда item pagination
недоступна, история читается штатными страницами `thread/turns/list`, без прямого чтения
JSONL и отдельного хранилища переписки. Пустые открытые разговоры видны на телефоне,
даже если Codex пока не включил их в `thread/list`; после первого сообщения название
на телефоне берётся из его превью. Явное название из Codex сохраняется.
Протокол: [официальная документация OpenAI](https://learn.chatgpt.com/docs/app-server#threads).

С версии 0.4.1 можно отправить до восьми картинок JPEG/PNG/WebP/GIF вместе с текстом или
без него: до 6 МиБ на картинку и 8 МиБ суммарно. Они передаются штатным `image` input
в `turn/start` или `turn/steer`, без записи файлов в проект и без смены разрешений.
После приёма оригинал хранит Codex; состояние контроллера содержит только число картинок
у неподтверждённой задачи. После аварии картинки не отправляются повторно автоматически.
На телефоне удобное удаление отдельных вложений и единая шапка сессии — в Баксе 0.75.6.
Протокол: [официальная документация OpenAI](https://learn.chatgpt.com/docs/app-server#turns).

Обновление MCP заменяет старый контроллер только когда у проекта нет фоновых задач,
очередей, неподтверждённых доставок и вопросов. Сохранённый выбор остаётся; старые окна MCP
не понижают версию контроллера. Занятая версия продолжает работу до безопасного перехода.

Асинхронные вопросы `request_user_input_async` приходят как `agentMessage` с полем
`questions`, а не как RPC-запрос разрешения. С версии 0.3.2 варианты показываются карточкой.
Ответ направляется в тот же активный ход через `turn/steer` с проверкой его ID; если ход
завершён, ответ идёт обычной задачей в тот же разговор. Неопределённая доставка не повторяется.
С версии 0.3.7 вопросы без вариантов тоже приходят карточкой, а вопросы, чьи поля появились
только при завершении сообщения, не пропускаются. В Баксе 0.75.4 карточка показывает
«Выберите вариант» и кнопки ответов либо «Ваш ответ» и поле ввода. Асинхронный вопрос
всегда допускает свой текст; обычный `request_user_input` — только при `isOther=true`
или отсутствии вариантов. Несколько вопросов показываются по очереди; Codex получает
все ответы вместе. Ответ не выдаёт доступ к команде или файлу. Пустой `agentMessage.text`
не скрывает вопрос из истории. Разрешения на команды по-прежнему выдаются только через
настоящий запрос Codex, на одно действие.

С версии **0.4.3** ответ из консоли в формате «текст вопроса → Ответ: …» закрывает
точную карточку автоматически. Свободный ответ вроде «Issuer ID: …» понимает агент:
он читает `bax_status.async_questions` и вызывает `bax_resolve_question` для отвеченного
вопроса. Это не отправляет ответ повторно, не создаёт ход и не меняет выбранную сессию.
Обычные сообщения без явного ответа карточку не снимают. Закрытие и ответы с телефона
передаются `question.resolved` всем подключённым устройствам этого пользователя.
Разрешения на команды, файлы и сеть этим инструментом закрыть нельзя.
Если поверхность Codex не передала MCP свой ID, оба инструмента принимают точный
`thread_id` из `CODEX_THREAD_ID`, проверяют его через app-server без выбора разговора.

## Модель, effort и время ответа

В Баксе 0.76.3 пункт **«Модель и effort»** в меню «…» открывается отдельно от общих
настроек агента. С версии **0.4.4** контроллер отдаёт актуальный каталог через официальный
`model/list`, проверяет допустимый effort и сохраняет выбор только для явно выбранного
разговора. При занятом ходе комментарии и фото продолжают поступать через `turn/steer`;
новые параметры применяются с ближайшим `turn/start`, без остановки работы. После
перезапуска контроллера ожидающий выбор сохраняется. Attach, sandbox и approval policy
не меняются; выбранная модель не применяется к остальным разговорам.

В `message` передаются необязательные `model`, `effort`, `created_at` (Unix-секунды)
и `turn_id` именно ответа. SDK timestamp используется, когда он доступен. Для legacy
истории параметры берутся из точного журнала, путь которого подтвердил `thread/read`:
проверяются ID и cwd, а элементы сопоставляются по ID или по хешу текста, ходу, phase
и порядку. При неоднозначном совпадении неизвестные поля не заполняются. Текущая модель
не подставляется в старые ответы. Журнал читается только для метаданных, текст ответов
и регистрация из него не сохраняются.

Основание API — [официальная документация OpenAI](https://learn.chatgpt.com/docs/app-server#models).

## Подтверждать действия с телефона

Плагин передаёт настоящие запросы разрешения от Codex. В **Ask for approval** запросы
сверх обычного рабочего доступа приходят человеку; в **Approve for me** подходящие
запросы рассматривает автоматический агент. Уведомления автоматической проверки не
превращаются в ручные карточки. Выбранный режим сохраняется; переключать его ради Бакса
не нужно. Отдельные обязательные подтверждения остаются по правилам самого Codex.
Основание — [официальная документация OpenAI](https://learn.chatgpt.com/docs/permission-modes).

Телефон показывает **«Нужно разрешение»** и кнопки **«Разрешить / Запретить»**.
С версии 0.3.4 поддержан `item/permissions/requestApproval`: видны сеть, пути и срок доступа.
Кнопка **«Разрешить»** выдаёт запрошенный профиль на текущий ход (`scope=turn`), отказ —
пустой профиль. С версии 0.3.5 есть третья кнопка с точным сроком:

- **«Разрешить всегда»** — только предложенное Codex правило начала команды или сетевого
  адреса. Правило видно до выбора; телефон не может подставить другую команду или адрес.
- **«Разрешить на диалог»** — подтверждение из session cache, правки под показанным
  `grantRoot` либо запрошенные сеть/пути с `scope=session`. Следующие диалоги его не наследуют.

`availableDecisions` ограничивает варианты команд; неподдержанный срок скрывает третью
кнопку. Для сети без предложенного правила и правок без абсолютного `grantRoot` она не
появляется. Старая версия приложения вместо третьей кнопки показывает прежний переключатель
с описанием срока. Новый UI кнопок — в Баксе 0.75.2.
Новые пути и правила из ответа телефона не применяются; выдача доступа требует выбора
человека. Сохранение правила не отключает обязательную автоматическую проверку Codex.
Запрос managed network показывает адрес и протокол. Решение в самом Codex или окончание хода закрывают карточку.
Чужие разговоры, другие ходы и повторные ответы отклоняются.

`bax_status.approvals` показывает policy/reviewer/manual на момент подключения.
Новый формат доступа проверяется типом `RequestPermissionProfile` SDK 0.160.0;
неизвестный формат остаётся для подтверждения в локальном Codex, с понятной ошибкой.
Протокол — [Codex app-server](https://learn.chatgpt.com/docs/app-server#permission-requests).

## MCP-инструменты

| Инструмент | Назначение |
| --- | --- |
| `bax_status` | Связь, проект, точный ID и ожидающие задачи; без секретов. |
| `bax_attach(thread_id)` | Явно выбрать точный открытый разговор своего проекта на телефоне. |
| `bax_connect(key, server)` | Сохранить регистрацию, которую человек скопировал из Бакса. |

Подключение и смену ключа разрешает только просьба человека в локальном чате;
задача с телефона не разрешает перепривязку. Навык не читает файл с ключами и не повторяет
секрет в ответе. Ключ сохраняется в `~/.bax/codex-light.json` с правами `0600`, отдельно от
Claude. Один ключ нельзя использовать в двух проектах. Регистрация другого агента в уже
подключённом проекте отклоняется; перевыпущенный ключ того же агента можно вставить заново.

Пишите ответы обычным способом: специального инструмента `reply` нет. Модель, sandbox,
approval policy и вложения настраиваются в Codex. Сессиями и остановкой задач управляет
экран проекта в Баксе. Самовольное изменение разрешений и выбор «последнего» разговора отсутствуют.

## Разработка и диагностика

Открытые задачи — в [BACKLOG.md](BACKLOG.md).

С версии 0.4.5 `systemError` означает ошибку последнего запроса в доступном разговоре.
Сессию можно открыть на телефоне, прочитать историю и отправить новое сообщение;
причина последней ошибки приходит отдельным кадром `error` с кодом `codex_turn_failed`.
Выгруженные разговоры (`notLoaded`) по-прежнему требуют открытия или восстановления.

```bash
uv sync --locked
.venv/bin/bax-codex-light doctor --project /absolute/path/to/your-project --check-history
```

`doctor` читает метаданные и проверяет историю, не показывает текст разговора и не запускает
ход. При отсутствии `CODEX_THREAD_ID` передайте точный ID через `--thread`. Успех:
`ok=true`, `history_ok=true`; `registered=false` означает, что проект ещё не подключён.

По умолчанию используется `$CODEX_HOME/app-server-control/app-server-control.sock`,
а без `CODEX_HOME` — `~/.codex/app-server-control/app-server-control.sock`.
Другой локальный адрес задаётся `--app-server` / `BAX_CODEX_APP_SERVER`;
поддерживаются UDS и `ws://127.0.0.1:PORT`, удалённый app-server запрещён.

Основные причины в `bax_status`:

| `error_code` | Как восстановить связь |
| --- | --- |
| `codex_unavailable` | Открыть или перезапустить Codex; адрес сокета указан в ошибке. |
| `codex_socket_permission_denied` | Запускать MCP штатно из Codex; ручному запуску в песочнице дать доступ к сокету. |
| `agent_busy` | Закрыть мост прежнего разговора, который ещё держит этого агента; новый мост повторит подключение. |
| `registration_missing` | Вставить команду регистрации из Бакса в нужный разговор. |
| `key_claimed` / `unauthorized` | Выпустить актуальную регистрацию в приложении и подключить её по просьбе пользователя. |
| `codex_thread_closed` | Подключить новый разговор его точным `CODEX_THREAD_ID`. |
| `timeout` / `network_unavailable` | Проверить сеть и адрес сервера. |

Код и сообщение отказа релея сохраняются, вместо одного `RuntimeError`.
Секреты регистрации в диагностике не выводятся.

Ручная регистрация для разработки остаётся доступной:

```bash
.venv/bin/bax-codex-light connect --project /absolute/path/to/your-project --server wss://relay.baxassist.com/agent
```

Она запрашивает ключ скрытым вводом; для автоматизации есть `--key-stdin`. Для старого
сервера `--compat-claude-lite` использует отдельного Claude Code Lite агента. Нативный тип
Codex Light требует сервер Бакса 0.44.0 и приложение 0.72.0; инструкция плагина — 0.73.0.
Дополнительных серверных ручек для плагина нет. Контракт — [docs/integration.md](docs/integration.md).

## Проверки

```bash
uv sync --locked
.venv/bin/ruff check plugins tests
.venv/bin/ruff format --check plugins tests
.venv/bin/pytest tests -q
```

Для проверки упакованного плагина один раз подготовьте **временное** окружение и выполните:

```bash
BAX_CODEX_PLUGIN_DATA=/private/tmp/bax-codex-plugin-runtime python3 plugins/bax-codex/bootstrap.py --prepare
BAX_TEST_PLUGIN_RUNTIME=/private/tmp/bax-codex-plugin-runtime .venv/bin/pytest tests -q
```

Сами тесты не скачивают зависимости. Они используют временные регистрации и локальные
имитаторы, проверяют HMAC, задачу в точный разговор, историю, разрешения, изоляцию,
переподключение и реальный STDIO MCP. Проверка установки использует настоящий CLI Codex,
временный `CODEX_HOME`, каталог с пробелами и сохранение остальных настроек.
Проверка первого запроса запускает штатный `codex exec` с задержкой bootstrap дольше
optional grace: в первом запросе присутствуют все три MCP-инструмента. Запрос принимает
локальный HTTP-имитатор; языковая модель не вызывается. Отдельно проверены недоступный
сокет, отказ доступа, восстановление связи, `agent_busy` и отключение закрытого разговора.
Реальный перезапуск 0.3.2 на Ubuntu нужно подтвердить на той машине.
Для тестов на loopback sandbox может потребовать разрешение.

Для обновления зависимостей после `uv lock`:

```bash
uv export --locked --no-dev --no-emit-project --no-header --no-annotate -o plugins/bax-codex/requirements.txt
```

Для проверки локальной версии добавьте этот каталог вместо GitHub:

```bash
codex plugin marketplace add /absolute/path/to/bax-codex-light-agent
codex plugin add bax-codex@baxassist
```

После каждой завершённой задачи изменения отправляются в `origin/main`:
`git@github.com:baxassist/bax-codex-light.git`.

API app-server experimental; типы SDK и новые версии Codex нужно проверять совместно.
Полный прогон с физическим телефоном и действующей моделью пока не выполнен.
Причина обрывов при погасшем экране на Mac подтверждена журналом `pmset`: вслед за экраном
система переходила в `Idle Sleep`. На Linux защита macOS не запускается.

### Сжатие с телефона (0.5.2)

Контроллер объявляет `context.get` и `session.compact`. Приложение запрашивает журнал
и после подтверждения запускает штатный `thread/compact/start` для точного выбранного
разговора. Занятый разговор, чужой проект и устаревший `expected_session` отклоняются.
Модель, разрешения и привязка сохраняются. `context.history` содержит время сжатия,
последний замер токенов до него и первый после, без текста сводки. Нет журнала или
замера — неизвестное значение, а не ноль; инициатор по журналу не угадывается.
